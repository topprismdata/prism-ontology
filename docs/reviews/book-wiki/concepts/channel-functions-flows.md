# 渠道功能与流（Channel Functions and Flows）

## 定义（综合多来源）

- **营销渠道**："一组相互依存的组织，参与使产品或服务可供使用或消费的过程。"（stern-marketing-channels, p.7；p.32 Take-aways 重申）关键点：渠道成员因"做渠道的工作"（channel work）而存在——中间商通过撮合搜寻、集货与分等（sorting）、减少接触次数来同时增值与降本。
- **渠道功能**：Kotler 给出可操作的功能清单——收集信息、开发并传播说服性沟通、谈判达成价格与条款、下订单、筹资持有库存、承担渠道工作风险、向买方提供融资与付款便利、监督所有权实际转移。三大共性："消耗稀缺资源、可通过专业化做得更好、可在渠道成员间转移。"问题从来不是"要不要执行这些功能"，而是"由谁来执行"。（kotler-marketing-mgmt-15e, p.351）
- **接触次数经济学**：制造商直销 4 家零售商需 40 条接触线路；经一家批发商降至 14 条；经两家为 28 条——中间商的价值主张首先是接触成本的结构性压缩（stern-marketing-channels, p.14，Figure 1）。

## 核心框架（逐个带出处页码）

### 1. Stern 的八条通用渠道流（Figure 2）
生产者→批发商→零售商→消费者每一环节上都可发生：**实体持有（physical possession）、所有权（ownership/title）、促销（promotion）、谈判（negotiation）、融资（financing）、风险承担（risking）、订购（ordering）、支付（payment）**。（stern-marketing-channels, p.17, Figure 2 "Marketing flows in channels"）
- 流的可分性与专业化："并非每个渠道成员都需要参与每一条流；渠道流的专业化分工是高效渠道的标志。"厂商代表（manufacturers' reps）不参与实体持有与所有权流——不碰货。（p.18）
- 流之间的耦合："任何一方持有并拥有库存，融资流即在进行"——批发商/零售商取货权并持货即是在为制造商融资，资金成本是持货的机会成本。（p.18）
- 不可消灭定理："你可以消灭或替代渠道成员，但成员执行的流不能被消灭——只会向前或向后转移并由其他成员承担。"消灭中间商省钱的唯一正当理由是这些流由别人做更有效率，而非省下那道毛利。（p.18）
- 谈判流定义："每当交易条款或持续关系的维护条款被讨论和决定时，谈判流即发生。"（p.96）

### 2. Kotler 的五种营销流（Figure 15.1）
实体流（正向）、所有权/_title 流（正向）、支付流（逆向）、信息流（双向）、促销流（正向，经由广告代理）。功能按方向分三类：储存运输/所有权/沟通为正向流，订购/支付为逆向流，信息/谈判/融资/风险承担为双向流。（kotler-marketing-mgmt-15e, p.351-352）
- 与 Stern 的对照：Kotler 的五流是八流的归并版（ordering 与 payment 合入逆向支付/订购、risking 并入双向），两书互为细/粗粒度。

### 3. 渠道层级（channel levels）
"渠道可用中间商层数描述。零层渠道（zero-level channel）即直接营销渠道：制造商直接卖给最终客户；中间商层数定义渠道的长度与宽度，层级越多，生产者越难实施控制。"（kotler-marketing-mgmt-15e, p.352）

### 4. 销售视角的渠道类型谱系（Table 4.1）
公司自有（直销队伍、电话渠道、官网、自营店）→ 公司连接（代理、经纪、特许、厂商代表）→ 独立（批发商、分销商、经销商、独立代理、增值伙伴、互联网中介）；判别维度是货权与控制。（zoltners-sf-design, p.123-124）

### 5. 快消行业渠道操作定义（INE 渠道定义总览）
可口可乐中国 INE 7.1 用客观可核查属性定义六大渠道：大卖场（≥6,000㎡、自选服务、>20 收银台、售冷冻与非快消品）、超市（1,000-6,000㎡）、小超市（<1,000㎡）、传统食杂（非自选、必须售香烟/酒/饮料至少其一）、传统餐饮（<10 张桌、客单≤15 元、店主兼服务员）、中高档餐饮（≥10 桌、有包房与制服服务员、客单 30-150 元）；并区分现代渠道与传统食杂/餐饮渠道计分权重。（ine-omnichannel-cn, p.11, p.12）
- 五项基本执行标准：产品铺货、SOVI 陈列、冰柜纯净度、渠道活动（二次陈列）、价格沟通。（p.9）
- 渠道覆盖按样本店数计量（大卖场 864 样本/超市 1540/小超市 3454/传统食杂 6714/餐饮合计 7130/乡镇 4844），以抽样镜像 Nielsen 口径。（p.6）

## 跨文献对照（一致/互补/分歧）

- **一致**：Stern 与 Kotler 都坚持"功能不可消灭、只能转移"（stern p.18 与 kotler p.351 几乎逐句同构，均源自 Alderson 功能主义传统），且都把"谁来执行每条流"作为渠道设计的核心问题。
- **互补**：Stern 提供流的**谱系与成员判别**（channel captain 概念：对渠道运转最关切并充任原动力的组织，常为品牌制造商，stern p.19）；Kotler 提供**方向性与层级语言**；zoltners-sf-design 把流视角用于**销售过程**（同一客户的五阶段可由不同渠道执行，p.122）；ine-omnichannel-cn 则展示渠道在快消一线如何被**操作化为可审计的售点类型学**与执行评分标准。
- **分歧/张力**：理论书（Stern/Kotler）按"流与层级"切渠道，行业实践（INE）按"业态属性+客单价"切渠道——两套分类不可互译（如"传统食杂"既可能是零层直供也可能是经一层经销商）。prism-ontology 需同时容纳两者：渠道是 Outlet 的分类属性（业态），而流是 ServiceRelationship 的属性（谁做哪条流），不应把二者混为同一分类轴。
- **术语澄清**："omnichannel（全渠道）"在本语料中未出现严格定义——ine-omnichannel-cn 实际是"all channels"市场执行审计标准，覆盖现代+传统全渠道组合，而非顾客旅程意义上的全渠道理论；引用时应作渠道覆盖与执行标准证据，而非 omnichannel 理论出处。

## 对 prism-ontology 的评审要点

1. **Outlet 的渠道分类缺依据字段**：INE 的渠道定义（p.11）给出权威示例——渠道判别属性应是**可核查的客观属性**（面积、服务形式、收银台数、售卖内容、桌数、客单价、员工制服），而非主观标签。建议 Outlet 的 `channelType` 附带 `classificationCriteria` 结构化属性集；乡镇渠道（p.6, p.12）提示本体还需覆盖下沉市场渠道枚举。
2. **缺"流"这一关系级概念**：现有 ServiceRelationship 只表达"谁服务谁"，缺 `ChannelFlowParticipation`（参与者×流类型×方向）。Stern p.17-18 的八流清单是权威枚举；salesforce-annual 视角的 POS/库存数据流、INE 的冰柜/陈列执行流都是其实例。缺失它，"经销商替厂家融资、承担库存风险"这类渠道经济本质无法表达。
3. **SOVI/铺货指标的口径锚点**：p.9 的五项标准与 p.8 的"KO 占 5 大饮料厂商冰柜门数占比"是 prism-ontology 已有 SOVI/MetricDefinition 的真实行业口径—— MetricDefinition 应记录"分母口径"（如冰柜门数占比是相对竞争集而非全店）。
4. **渠道层级 vs 拜访线路**：Kotler p.352 的层级控制递减律解释了为何品牌方需要终端执行审计（层级越多越难控制）；这为 Observation/InsightClaim 提供了"为什么要派驻/巡店"的理论依据，属本体可保留的动机性语义。
5. **保持策略层**：渠道设计（谁执行哪条流）不是执行类概念，是 ServiceRelationship 的类型属性，符合架构禁令。
